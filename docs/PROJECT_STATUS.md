## 2. 已完成

### 2.1 仓库与发布边界

- Studio、协议、Device Agent、设备驱动和设备镜像已经拆成五个独立 Git 仓库。
- 各仓库可以独立测试和构建；协议与 Studio 可生成带 SHA-256 的发布压缩包。
- 镜像仓库可以按组件目录装配 Agent、Studio 和独立驱动，不复制子仓库的 `.git`。
- CI 已覆盖协议校验、Studio 语法检查、Agent 回归、驱动契约测试和镜像锁检查。

### 2.2 公共协议与兼容管理

- 已定义协议版本协商、Driver API 版本范围、驱动清单和固件清单 Schema。
- `.zdp` 驱动包和 `.zfw` 固件包支持安全路径检查、大小限制、SHA-256 校验和 Ed25519 验签。
- 组件锁明确固定 Studio、Agent、Drivers 和 Protocol 版本。

### 2.3 可插拔设备驱动

- 已定义舵机、ToF、摄像头、风扇和 IMU 五类稳定接口及统一生命周期。
- 已提供首批型号适配器：
  - Feetech STS/SCS 舵机；
  - ST VL53L5CX ToF；
  - V4L2 / libcamera 摄像头；
  - Radxa Zero 3W 双路 PWM/Tach 风扇；
  - QMI8658、MPU6050、ICM42688 IMU 自动探测。
- 驱动目录支持按稳定驱动 ID 查询和创建实例。
- Agent 仍保留旧镜像内置驱动作为兼容回退。

### 2.4 驱动选择到 HAL 的闭环

- Studio 可以查看当前型号、运行驱动、版本、兼容性和健康状态。
- 用户选择会写入设备选择文件，并明确标记为“待重启生效”。
- Agent 在创建 HAL 之前读取选择文件，使用独立驱动工厂分别创建五类设备实例。
- 某一类驱动构造或启动失败时，只回退该类设备的默认驱动，不影响其他设备。
- 实际加载结果、回退状态和错误原因会回传 Studio。
- 旧版五个驱动 ID 会自动迁移到新的稳定 ID。

### 2.5 固件管理的安全前置能力

- Studio 可以显示已验证固件、目标型号、当前/目标版本、驱动要求、签名状态、风险等级和不兼容原因。
- 固件候选按实际识别型号、活动驱动版本和签名信任状态筛选。
- 支持从设备收件箱校验并暂存 `.zfw`。
- 支持升级前检查，包括包完整性、活动驱动、驱动版本、刷写能力、签名，以及舵机场景的卸力、姿势和急停状态。
- Studio 已预留升级任务进度和结果展示；写入未启用时“开始升级”保持禁用，不会伪装成功。

### 2.6 当前验证基线

- Agent 完整回归共 121 个测试通过。
- 独立驱动工厂成功创建五类 HAL 实例。
- 所选驱动启动失败后的逐设备回退测试通过。
- Studio JavaScript 语法检查和 1.1.1 发布打包通过。
- 镜像装配后可以加载 Agent 1.2.0 和 Drivers 1.1.0。
- 五个仓库在本阶段提交后均无未提交修改。

## 3. 未完成

### 3.1 真实固件刷写

当前只完成验证、暂存、兼容筛选和升级前检查，尚未：

- 进入设备 Bootloader；
- 擦除和写入固件；
- 写后校验；
- 重启外设并读取新固件版本；
- 实现超时、重试、断电恢复和失败回滚；
- 针对舵机、ToF、摄像头、风扇控制器和 IMU 分别实现厂商刷写后端。

没有独立可升级固件的设备，需要在型号清单中明确标记为不支持升级。

### 3.2 在线发布体系

- 五个仓库尚未配置远程 Git 地址，也未推送到远程平台。
- 尚无驱动/固件远程版本索引和 Studio 在线下载链路。
- 尚无从 Git Tag 自动构建、签名、上传 `.zdp`/`.zfw` 并更新索引的流水线。
- 生产签名私钥保管、公钥下发、轮换和吊销流程尚未建立。

### 3.3 真机交付验证

- 尚未在全部目标型号上完成端到端硬件验收。
- 尚未完成错误型号、错误驱动、错误签名、总线占用和设备掉线测试。
- 尚未完成升级过程中断电、断线、写入失败和恢复测试。
- 尚未生成并验收正式生产镜像。

## 4. 当前限制

- 已安装的 `.zdp` 目前只会安全暂存；只有已随镜像安装并注册到 `zelux-device-drivers` 的可执行实现才能被 HAL 工厂加载。
- 固件版本读取仍依赖驱动报告；部分硬件只能识别型号，不能读取真实固件版本。
- 驱动切换采用“保存后重启生效”，当前不支持不停机热切换。
- 本地提交尚未备份到远程仓库，暂停期间必须备份整个工作目录。

## 5. 恢复开发的推荐入口

下一阶段从真实固件升级任务状态机开始：

1. 定义统一 `FirmwareFlasher` 接口和任务持久化格式；
2. 选择一种真实设备先完成 `prepare → bootloader → erase → write → verify → reboot → confirm`；
3. 将任务进度接到现有 `firmware.job` 状态；
4. 在 Studio 解锁兼容固件的“开始升级”；
5. 完成失败回滚和断电恢复测试后，再扩展到其他设备类型。
